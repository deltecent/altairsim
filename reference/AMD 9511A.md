# AMD Am9511A Arithmetic Processor (Intel 8231A)

Sources:
- [1980_AMD_MOS_LSI_Data_Book.pdf](#) — the **Am9511A data sheet**, printed pp.7-66 to 7-90
  (PDF pp.285–309). The primary source for every register, command and timing figure here.
- [Am9511_Algorithm_Details.pdf](#) — AMD application brief *Algorithm Details for the Am9511
  Arithmetic Processing Unit*, R. O. Parker and J. H. Kroeger, © 1978, AM-PUB072, 21 printed
  pp. The data sheet's reference 2. Its command pages repeat the data sheet; it adds the
  status-bit figure (p.2), the stack-byte figure (p.3) and the error graphs (pp.6–7).
- [Am9511A-9512FP_Processor_Manual.pdf](#) — AMD *Am9511A/Am9512 Floating Point Processor
  Manual*, Steven Cheng, © 1981, RMC-615. Cited "FPM". Ch.8 has measured execution times;
  ch.9 has the transcendental algorithms and every Chebyshev coefficient. **The scan stops at
  printed p.55** — appendices A and B (the two data sheets) are not in it.
- [CompuPro System Support 1 Manual.pdf](#) — cited "SS-1". pp.70–72 (the math-chip test
  program), pp.91–93 (board wiring). pp.73–78 reprint Intel's **8231A** preliminary data sheet
  (corroboration only; where Intel and AMD differ, AMD wins — the SS-1 stencil names the AMD
  part, U13-9511A/9512).

The **Am9511A** is a 24-pin NMOS "arithmetic processing unit" (APU): 16- and 32-bit two's
complement fixed point, a 32-bit floating-point format of its own (not IEEE), four float
operations, eleven derived functions (SQRT, SIN … PWR) and data/stack commands. All traffic
goes over an 8-bit bus through two ports; operands live on an internal LIFO stack. It replaces
the Am9511 (same commands; the 9511A adds the PAUSE timing fix). Intel second-sourced it as the
**8231A**. Clock: 2 MHz (Am9511A) or 3 MHz (Am9511A-1). On the
[CompuPro System Support 1](CompuPro%20System%20Support%201.md) it is the optional chip in the
math socket at base+8/+9.

Its successor, the [Am9512](AMD%209512.md), has **different** commands and number formats.

## 1. Quick reference for emulation

| Item | Value |
|---|---|
| Ports | C/D̅ = 0: data (push on write, pop on read). C/D̅ = 1: command (write), status (read) |
| Stack | 16 bytes as a ring: 8 × 16-bit or 4 × 32-bit entries; a byte pointer; no overflow detect |
| Byte order | push **LS byte first**, MS byte last; pop gives **MS byte first** |
| Command byte | bit 7 = SR (service request on completion); bits 6–0 = operation |
| Status | bit 7 BUSY, 6 SIGN, 5 ZERO, 4–1 error code, 0 CARRY |
| END (pin 24) | active **LOW**, open drain; set at command completion; cleared by EACK̅ low, **any** read or write (a status read included, p.7-67), or RESET |
| SVREQ (pin 5) | active HIGH; set at completion of a command with SR = 1; cleared by SVACK̅ low, RESET, or completion of a command with SR = 0 |
| PAUSE̅ (pin 17) | low during every access; held low until the running command ends if a data read/write or command write arrives while BUSY. A status read never waits for BUSY |
| RESET (pin 22) | high ≥ 5 CLK: stops the command, clears status to 0, initializes the stack pointer; stack *contents* may change; END goes HIGH (inactive) |
| Clock | Am9511A 2 MHz max (TCY 480–5000 ns), Am9511A-1 3 MHz |
| Execution | clock cycles from the command write to completion (§5) |

## 2. Interface (data sheet pp.7-67, 7-68, 7-70)

### 2.1 Port decode

| C/D̅ | RD̅ | WR̅ | Function |
|:---:|:---:|:---:|---|
| L | H | L | Push data byte into the stack |
| L | L | H | Pop data byte from the stack |
| H | H | L | Enter command byte |
| H | L | H | Read status |
| X | L | L | Undefined |

CS̅ must be low for any access. On the SS-1, base+8 is data, base+9 is command/status (§8).

### 2.2 Stack and byte order (pp.7-67, 7-70; Algorithm Details pp.2–3)

- Operands are **pushed least-significant byte first**, most-significant last. Results are
  **popped most-significant byte first**. Single precision fixed point = 2 bytes; double
  precision fixed point and floating point = 4 bytes.
- The stack holds **8 × 16-bit or 4 × 32-bit** values. Pushing more than that "will result in
  loss of data which is usual with any LIFO stack" — the oldest bytes are overwritten.
- "Reading of the stack does not alter its data; it only adjusts the byte pointer. If more
  data is popped than the capacity of the stack, the internal byte pointer will wrap around and
  older data will be read again." The stack is a 16-byte ring with a byte pointer.
- Pushing or popping a number of bytes that is not a whole operand leaves the byte pointer
  misaligned; commands then take the wrong bytes. There is no realign command; RESET re-inits
  the pointer (SS-1 p.70 says the same).
- Intel 8231A sheet (SS-1 p.76): "Data on the bottom of the stack prior to a stack entry are
  lost"; "Data removed from the stack rotates to the bottom of the stack."

Algorithm Details Fig. 6 (p.3), the byte sequence of a 32-bit add: push C1..C4 (C1 = LS byte),
then B1..B4, then A1..A4; after FADD/DADD the TOS holds R4 R3 R2 R1 over C; popping R4 (MS)
first leaves "R3 R2 R1 C4" — i.e. the pointer just moves down the ring.

### 2.3 Command word (p.7-68)

| 7 | 6 | 5 | 4–0 |
|---|---|---|---|
| SR | SINGLE | FIXED | operation |

- **FIXED** (bit 5) = 1: fixed-point data; 0: floating point.
- **SINGLE** (bit 6) selects the precision of a fixed-point command: 1 = 16-bit, 0 = 32-bit.
  For floating-point commands (bit 5 = 0) bit 6 must be 0.
- **SR** (bit 7) = 1: SVREQ goes high at the end of this command and stays high until SVACK̅,
  RESET, or the end of a later command with SR = 0.
- "Results are undefined for all illegal combinations of bits in the command byte" (p.7-68)
  and "for any combination of command coding bits not specified in this table" (p.7-69 note 6).

### 2.4 Status register (p.7-71; Algorithm Details Fig. 4 p.2)

| Bit | Name | Meaning |
|:---:|---|---|
| 7 | BUSY | 1 = a command is executing. **While BUSY = 1 the other bits are not defined.** |
| 6 | SIGN | 1 = the value on TOS is negative |
| 5 | ZERO | 1 = the value on TOS is zero |
| 4–1 | ERROR CODE | see below |
| 0 | CARRY | 1 = the last operation made a carry or borrow out of the MS bit |

Error code (bits 4 3 2 1):

| Code | Meaning |
|---|---|
| 0000 | No error |
| 1000 | Divide by zero |
| 0100 | Square root or log of a negative number |
| 1100 | Argument of inverse sine, cosine, or e^x too large |
| XX10 | Underflow |
| XX01 | Overflow |

Algorithm Details Fig. 4 gives the same layout bit by bit: bit 1 overflow, bit 2 underflow,
bits 4–3 = 01 negative argument, 10 zero divisor, 11 argument too large.

The status register can be read at any time, busy or not (p.7-70). Reading it while a command
runs can "conflict with internal logic setting of the END flip-flop" (p.7-67).

### 2.5 Handshake signals (pp.7-67, 7-68, 7-88; FPM ch.6–7)

- **END̅** — goes LOW when a command completes. Cleared HIGH by EACK̅ low, by "performing any
  read or write operation", or by RESET. A read or write clears it "after the HIGH to LOW
  transition of the RD̅ [WR̅] input". With EACK̅ tied low, END̅ is a pulse about one CLK wide.
  FPM p.25: "the END output will stay LOW until the first read/write operation is performed on
  the Am9511A, thus clearing the interrupt request."
- **SVREQ** — see §2.3. The NOP command "may be used to set or clear the service request
  interface line without changing the contents of the stack."
- **PAUSE̅** (Intel: READY, active high) — the bus handshake. On a read it goes low TRP after
  RD̅ and returns high when data is valid: TPPWR = 3.5 TCY + 50 ns min for a data read,
  1.5 TCY + 50 ns min for a status read (p.7-88). On a write it is low only very briefly
  (TPPWW, 50 ns max) "as long as the duty cycle requirement (TWI) is observed and no previous
  command is being executed." **If a previously entered command is still executing, PAUSE̅
  stays low until it completes** (p.7-88 notes 5, 8): "An attempt to issue a new command while
  the current command execution is in progress is allowed. Under these circumstances, the
  PAUSE output will not go HIGH until the current command execution is completed" (p.7-70). FPM
  ch.7.2: in demand/wait mode "the programmer can regard the Am9511A as always ready for READ
  and WRITE operations. If the Am9511A is not ready, the PAUSE will go LOW to put Am9080A in the
  WAIT state. When the Am9511A has completed the current operation, the PAUSE will go HIGH."
- **TWI** — a write must not follow the last one within 3 TCY (command) / 4 TCY (data),
  "may be safely violated as long as the extended TPPWW that results is observed".
- FPM p.27 (Z80 interface): PAUSE̅ "remains LOW for 3.5 TCY + 50ns (min) for data read and is
  LOW for 1.5 TCY + 50ns (min) for status read" — same figures.

### 2.6 Reset (p.7-67; Intel p.74)

RESET high for at least five CLK periods: terminates any command, clears the status register
to zero, initializes the internal stack pointer. AMD: "The contents of the stack may be
affected but the command register is not affected by the reset operation. After a reset the
END output will be HIGH, and the SVREQ output will be LOW." Intel 8231A: "Stack contents and
command registers are not affected."

## 3. Number formats (pp.7-70, 7-71; FPM ch.4)

- **16-bit fixed point**: two's complement, −32,768 … +32,767.
- **32-bit fixed point**: two's complement, −2,147,483,648 … +2,147,483,647.
- **32-bit floating point**:

| Bit 31 | Bits 30–24 | Bits 23–0 |
|---|---|---|
| mantissa sign (0 = +) | exponent, 7-bit **two's complement**, −64 … +63 | mantissa, 24-bit fraction, **binary point left of bit 23** |

  value = mantissa × 2^exponent, 0.5 ≤ mantissa < 1. **All floating-point values must be
  normalized: bit 23 = 1**, except zero, which is **all 32 bits zero**. There is no hidden bit
  and no exponent bias. Range ±2.7 × 10⁻²⁰ … ±9.2 × 10¹⁸ (Intel p.76; the AMD sheet prints
  10¹⁶ — ⚠ a typo: (1 − 2⁻²⁴) × 2⁶³ = 9.22 × 10¹⁸).
- Example (p.7-71): 100.5 = 0.11001001 × 2⁷.
- Worked encodings (FPM Tables 8.1/8.3; the hex was made by a BASIC converter, see ⚠ §9):
  `5 = 03A00000`, `6 = 03C00000`, `0.6 = 00999999`, `123 = 07F60000`, `456 = 09E40000`,
  `12345 = 0EC0E400`, `−678 = 8AA98000`, `−1.234 = 819DF3B6`, `0.0006 = 769D4951`.
- FPM Fig. 4.5a (BASIC, decimal → 9511A): exponent E = INT(LOG(D)/LOG(2)) + 1,
  mantissa M = D / 2^E; a negative exponent is stored as two's complement in bits 30–24.

## 4. Commands (pp.7-69, 7-72, 7-74 … 7-86)

TOS = top of stack, NOS = next on stack. A = the operand at TOS before the command, B the one
below it, then C, D (32-bit view) or C…H (16-bit view). Hex codes are for SR = 0; set bit 7 for
SR = 1. "lost" = the data sheet's crossed-out "Stack Contents After" cells (scratch storage the
command used; their contents are not specified).

### 4.1 16-bit fixed point

| Mnem | Hex | Cycles | Operation | Stack after (16-bit view) | Status |
|---|---|---|---|---|---|
| SADD | 6C | 16–18 | B + A | R C D E F G H A | S Z C E |
| SSUB | 6D | 30–32 | B − A | R C D E F G H A | S Z C E |
| SMUL | 6E | 84–94 | B × A, low 16 bits | R C D E F G H lost | S Z E |
| SMUU | 76 | 80–98 | B × A, high 16 bits | R C D E F G H lost | S Z E |
| SDIV | 6F | 84–94 (A ≠ 0); 14 (A = 0) | B ÷ A, no remainder | R C D E F G H lost | S Z E |

### 4.2 32-bit fixed point

| Mnem | Hex | Cycles | Operation | Stack after | Status |
|---|---|---|---|---|---|
| DADD | 2C | 20–22 | B + A | R C D A | S Z C E |
| DSUB | 2D | 38–40 | B − A | R C D A | S Z C E |
| DMUL | 2E | 194–210 | B × A, low 32 bits | R C D lost | S Z E |
| DMUU | 36 | 182–218 | B × A, high 32 bits | R C D lost | S Z E |
| DDIV | 2F | 196–210 (A ≠ 0); 18 (A = 0) | B ÷ A | R C D lost | S Z E |

Fixed-point rules (per command page):
- Add/subtract: carry or borrow → CARRY. "If the result is too large to be represented by the
  data format, the least significant 16 [32] bits of the result are returned and overflow
  status is reported." SSUB/DSUB: "If A is the most negative value that can be represented in
  the format the overflow status is set."
- Multiply lower (SMUL/DMUL): overflow is set "if the discarded upper half was non-zero. If
  either A or B is the most negative value that can be represented in the format, that value
  is returned as R and the overflow status is set."
- Multiply upper (SMUU/DMUU): "If either A or B is the most negative value … that value is
  returned as R [SMUU] / R is meaningless [DMUU] and the overflow status is set."
- Divide: "If A is zero, R will be set equal to B and the divide-by-zero error status will be
  reported." DDIV: "If either A or B is the most negative value possible in the format, R will
  be meaningless and the overflow error status will be reported." Note 5 (p.7-69): "No
  remainder is available for the fixed-point divide functions."

### 4.3 32-bit floating point primary

| Mnem | Hex | Cycles | Operation | Stack after | Status |
|---|---|---|---|---|---|
| FADD | 10 | 54–368 (A ≠ 0); 24 (A = 0) | B + A | R C D lost | S Z E |
| FSUB | 11 | 70–370 (A ≠ 0); 26 (A = 0) | B − A | R C D lost | S Z E |
| FMUL | 12 | 146–168 | B × A | R C D lost | S Z E |
| FDIV | 13 | 154–184 (A ≠ 0); 22 (A = 0) | B ÷ A | R C D lost | S Z E |

- "Exponent alignment before the addition and normalization of the result accounts for the
  variation in execution time."
- **Overflow/underflow: "in which case the mantissa is correct and the exponent is offset by
  128."** (FADD, FSUB, FMUL, FDIV.) Command descriptions (p.7-73): "the exponent returned in the
  result will be 128 greater or smaller than its true value." — i.e. the 7-bit exponent field
  wraps modulo 128.
- FDIV: "If operand A is zero, R is set equal to B and the divide-by-zero error is reported."

### 4.4 Derived floating-point functions

| Mnem | Hex | Cycles | Operation | Stack after | Status | Max error |
|---|---|---|---|---|---|---|
| SQRT | 01 | 782–870 | √A | R B C lost | S Z E | (see FPM Fig. 9.4) |
| SIN | 02 | 3796–4808 (\|A\| > 2⁻¹²); 30 (\|A\| ≤ 2⁻¹²) | sin A | R B lost lost | S Z | 5.0 × 10⁻⁷ rel, −2π … +2π |
| COS | 03 | 3840–4878 | cos A | R B lost lost | S Z | 5.0 × 10⁻⁷ rel, −2π … +2π |
| TAN | 04 | 4894–5886 (\|A\| > 2⁻¹²); 30 (\|A\| ≤ 2⁻¹²) | tan A | R B lost lost | S Z E | 5.0 × 10⁻⁷ rel, −2π … +2π except near odd π/2 |
| ASIN | 05 | 6230–7938 | arcsin A, −π/2 … +π/2 | R lost lost lost | S Z E | 4.0 × 10⁻⁷ rel |
| ACOS | 06 | 6304–8284 | arccos A, 0 … π | R lost lost lost | S Z E | 2.0 × 10⁻⁷ rel |
| ATAN | 07 | 4992–6536 | arctan A, −π/2 … +π/2 | R B lost lost | S Z | 3.0 × 10⁻⁷ rel |
| LOG | 08 | 4474–7132 (A > 0); 20 (A ≤ 0) | log₁₀ A | R B lost lost | S Z E | 2.0 × 10⁻⁷ abs for 0.1 … 10, else 2.0 × 10⁻⁷ rel |
| LN | 09 | 4298–6956 (A > 0); 20 (A ≤ 0) | ln A | R B lost lost | S Z E | 2 × 10⁻⁷ abs for e⁻¹ … e, else 2.0 × 10⁻⁷ rel |
| EXP | 0A | 3794–4878 (\|A\| ≤ 1.0 × 2⁵); 34 (\|A\| > 1.0 × 2⁵) | e^A | R B lost lost | S Z E | 5.0 × 10⁻⁷ rel |
| PWR | 0B | 8290–12032 | B^A | R C lost lost | S Z E | < 7.0 × 10⁻⁷ rel for most practical uses |

Argument rules (command pages):
- SQRT: any non-negative input; negative → error 0100.
- SIN/COS/TAN: any representable input; reduced to −π/2 … +π/2 (TAN: −π/4 … +π/4). TAN "is
  unbounded for input values near odd multiples of π/2 and in such cases the overflow bit is
  set". "For angles smaller than 2⁻¹² radians, TAN returns A as the tangent of A" (SIN the
  same, by its 30-cycle short path).
- ASIN/ACOS: −1.0 … +1.0; outside → error 1100.
- LOG/LN: any positive input; non-positive → error 0100.
- EXP: −1.0 × 2⁺⁵ … +1.0 × 2⁺⁵; outside → error 1100.
- PWR: B must be positive (non-positive B → error 0100); implemented as B^A = EXP[A × LN B],
  so A × LN B outside ±1.0 × 2⁺⁵ → error 1100. "Underflow and overflow conditions can occur."
- p.7-69 note 4: "The trigonometric functions handle angles in radians, not degrees."
- p.7-69 note 3: "Many commands destroy one stack location (bottom of stack) during
  development of the result. The derived functions may destroy several stack locations."

- FIXS/FIXD: "If the integer portion of A is larger than 15 [31] bits when converted, the
  overflow status will be set and A will not be changed. Operand D, however, will still be
  lost." FIXS: "Operands B and C are unchanged, but appear as upper (u) and lower (l) halves
  on the 16-bit wide stack if they are 32-bit operands."
- FLTS: "The lower half of the result R (Rl) replaces A, the upper half (Ru) replaces H and
  the stack is moved down so that Ru occupies the TOS. Operands A, F, G and H are lost."
- CHSS/CHSD: "Overflow status will be set and the TOS will be returned unchanged when A is
  input as the most negative value possible in the format since no positive equivalent
  exists."
- CHSF: "If A is input as zero (mantissa MSB = 0), no change is made."

  commands move the stack up; "the previous TOS rotates to the bottom of the stack."
- Hex code summary and execution cycles: data sheet Table 1 (p.7-72) = Algorithm Details
  Fig. 8 (p.4). Mnemonics in alphabetical order: Table 2 (p.7-73).

## 6. Derived-function algorithms (FPM ch.9, printed pp.50–55)

"Each of the derived functions except square root implemented in the Am9511 APU has been
reduced to Chebyshev polynomial form. A sufficient number of terms has been used to provide a
mean relative error of about one part in 10⁷" (Algorithm Details p.5). Three steps: range
reduction, Chebyshev evaluation, post-processing. The coefficients "are all precalculated and
stored in the constant ROM" (FPM 9.2). The text below is as printed; ⚠ marks a printed formula
that does not close, with the form that does (each checked against host math, worst error over
the stated range given in brackets).

**CHEBY** (FPM 9.3): f(x) = ½C₀ + Σₖ₌₁ⁿ⁻¹ Cₖ Tₖ(x). The faster FORTRAN form as printed:

```
FUNCTION CHEBY (X, C, N)
DIMENSION C(12)
B = 0
D = C(N)
X2 = 2 * X
DO 100 I = N, 2, -1
A = B
B = D
100 D = X2 * B - A + C(I - 1)
CHEBY = (D - A)/2
END
```

**ENTIER** (FPM 9.3): rounds down to the lower integer (ENTIER(−2.5) = −3), unlike INT.

**SIN** (9.4): `X = X*2/π`; `X = X − 4*Entier((X+1)/4)`; `If (X.GT.1) X = 2 − X`;
Sin = X × CHEBY(2X² − 1, Csin, 6). ⚠ Printed "2X² − 0.1"; 2X² − 1 closes [4.3 × 10⁻⁸ rel].

| k | Csin_k |
|---|---|
| 0 | 2.5525579 |
| 1 | −0.2852616 |
| 2 | 9.118016 × 10⁻³ |
| 3 | −1.365875 × 10⁻⁴ |

X₁ = (M/X₀ + X₀)/2, X₂ = (M/X₁ + X₁)/2. SQRT = X₂ × 2^(E/2). FORTRAN as printed:

```
INTEGER EXPO, LSB
REAL MANT, X0, X1, X2
EXPO = INT (LOG(X)/LOG(2)) + 1
MANT = X/2**EXP
LSB = MOD(EXPO, 2)
IF (LSB.EQ.0) GOTO 100
C EXPONENT IS ODD
EXPO = EXPO + 1
MANT = MANT/2.0
100 X0 = 0.68629150* Mant + 0.34314575
X1 = (X/X0 + X0)/2.0
X2 = (X/X1 + X1)/2.0

```

for LN) over the input range. SIN, COS and TAN errors grow without bound for |x| far beyond
2π (to 10⁰ relative near 10¹⁰ radians) — range reduction in 32-bit arithmetic. ASIN, ACOS,
ATAN, SQRT, LN, EXP stay near or below 10⁻⁷. PWR: |RE_PWR| = |RE_EXP| + |X × AE_LN|.

### 6.1 What the real chip does (measured, #908)

Two CompuPro System Support 1 boards with two 9511A chips ran the cases of issue #908. The
second board also ran about 450 more cases (2026-11-08). The test program pushed three marker
values under the operand and popped all 16 bytes after the command. The chip leaves
intermediate values in the stack cells under the result, often unnormalized. These values
show the steps below. The data is in `tests/test_am9511a.cpp` (`kReal`, 550 cases).

**The four float operations truncate.** There are no guard bits and no rounding.

- FADD and FSUB align the smaller operand with a right shift that drops its low bits.
- FMUL is a 24-step shift-and-add. Each step drops one bit.
- FDIV gives 24 quotient bits when B's mantissa ≥ A's. Else it gives 23 bits and a 0.
- FLTD truncates. PUPI pushes `02C90FDA`, π cut to 24 bits.

**The ROM coefficients are the exact Chebyshev coefficients, cut to 24 bits.** They are not
the 8-digit decimals that §6 prints. Thirteen coefficients differ from the cut decimal in the
last bit, for example EXP C₀: `01BA7EF8` (exact), `01BA7EF9` (1.4569999 cut). Only the exact
coefficients give the real results.

| Function | The steps on the real chip |
|---|---|
| SIN | Y = X / (π/2), cut to 23 significant bits. §6 SIN works on Y. |
| COS | The SIN steps on (π/2 − X), with the chip's FSUB. COS(−X) and COS(X) differ in the low bits. |
| TAN | Y = X / (π/4) (FDIV). §6 TAN works on Y. At a pole the cotangent's FDIV divides 1 by 0: status 10, R = 1.0. |
| ATAN | §6 ATAN, with the reciprocal at \|X\| = 1 too (ATAN 1 = `00C90FD8`). |
| ASIN | The §6 ASIN series is not used. W = (1 − \|X\|)(1 + \|X\|), Q = SQRT(W). If \|X\|/Q < 1, ASIN = ATAN series of \|X\|/Q. Else ASIN = π/2 − ATAN series of Q/\|X\|. The sign of X goes on the result. |
| ACOS | π/2 − ASIN, with the chip's FSUB. |
| EXP | X / LN 2 (FDIV), then §6 EXP. |
| LN, LOG, SQRT, PWR | As §6, with the four operations above. |

The CHEBY steps are as §6 prints them. The cell under the result holds −A aligned with D,
from the last subtraction.

**Where the simulator still differs.** The simulator follows the steps above and gives the
real status and result in 507 of the 550 cases. In 35 cases of SIN, COS, ATAN, ASIN, ACOS,
EXP and PWR, the result is 1 or 2 LSB from the real one. In 8 SIN and COS cases, the real
chip's reduced argument has a 24th quotient bit. With 24 bits, 7 of those cases give the real
result. No rule for the 24th bit is known.

**The real chip goes past the data sheet's error figures.** Measured:

- LOG: 3.8 × 10⁻⁷ at 7.41.
- EXP: 1.9 × 10⁻⁶ relative at −31.9.
- COS: 6.1 × 10⁻⁷ relative at −0.963.
- ASIN: 5.2 × 10⁻⁷ relative at 0.9965.
- ACOS: 1.4 × 10⁻⁴ absolute at 0.99999994.
- PWR: 2 ^ 10 = `0AFFFFF4`.

**Argument errors stop early.** The time is from the poll counts, at about 32 clocks for each
poll.

- SQRT of a negative value: status 48. R keeps the mantissa, with sign 1 and exponent 0
  (−4 → `80800000`). 20 clocks. SQRT 0: 20 clocks.
- ASIN and ACOS with \|X\| > 1: about 140 clocks. LN, LOG and PWR with B ≤ 0: 20 clocks.
- FIXS and FIXD overflow: 20 clocks.
- PWR with \|A × LN B\| > 32: the chip stops after the LN and the FMUL. R = A × LN B, status 18.

**The most negative value.** SMUL and DMUL return the low half of the product. SMUU and DMUU
return the high half, except B = 8000 (80000000) times a negative A, which gives `7FFF`
(`7FFFFFFF`). SDIV and DDIV with an operand at the most negative value return 0. Overflow is
set in each case. B = 8000 divided by a negative A: `FFFF` gives `FFFE`, `FFFE` gives `FFFC`,
`C000` gives `AAAA`. No rule for these is known.

## 7. Interface programs (FPM ch.7, pp.32–41)

Four methods, with 8080 listings (Fig. 7.1–7.4; APU at ports C0H data, C1H status/command):

- **Demand/wait** (Fig. 7.1): push 4 bytes of each operand LS byte first (pointer starts at
  the operand's LSB and decrements), `OUT` the command, then `IN` the 4 result bytes at once —
  "If the APU is not ready, the PAUSE signal will put AM9080A into the 'WAIT' state until the
  data is ready" — then `IN` the status.
- **Poll status** (Fig. 7.2): read status until bit 7 (BUSY) is clear before the pushes, and
  again after the command, before the pops.
- **Interrupt driven** (Fig. 7.3): the END̅ line to the CPU's INT through an INTA pull-up that
  makes an RST 7; the handler at 38H pops the result. "By pulling the EACK HIGH, the END output
  will stay LOW until the first read/write operation is performed".
- **DMA** (Fig. 7.4/7.5): Am9517A channels 2/3 load and unload the stack; Am9519 interrupts.

## 8. On the CompuPro System Support 1 (SS-1 pp.70–72, 91–93)

- Ports: base+8 data, base+9 command/status (standard base 50H → 58H/59H).
- The chip runs from the 2 MHz S-100 bus CLOCK (pin 49); jumper J5 can select an on-board
  oscillator (crystal X1 ÷ 2) for a faster part.
- PAUSE̅ drives the bus RDY line (inverted by U11, re-inverted by U28). **Two wait states are
  inserted automatically on every math-chip access**, "because the PAUSE output of the 9511
  (8231) comes out too late to cause a wait state … if the 9511 needs more, its PAUSE line will
  remain asserted, extending the wait state further" (p.93).
- END and SVREQ go to the interrupt structure (slave 8259A IR5/IR4 in the stock shunt). "The
  ERROR signal is only available on the 9512 (8232) and the END polarity is different between
  the two types of math chips. J6 is used to correct for the polarity difference" (p.92).

## Quirks worth carrying

- **Float results are truncated, not rounded** (measured on two chips, §6.1). The FPM hex
  encodings one LSB below truncation (.006 → `79C49BA4`, .06 → `7CF5C28E`) fit the
  shift-and-add FMUL.
- FIXS and FIXD drop the fraction (toward zero), measured: FIXD −2.5 = −2, FIXS −3.5 = −3. The
  command pages say "the integer portion of A".
- SMUL and DMUL set overflow when the product does not fit the signed format, or when an
  operand is the most negative value. The result is the low half of the product (§6.1).
- **The data sheet's error figures are typical, not limits.** The Algorithm Details graphs
  (pp.6–7) plot the error over a sample of inputs. The real chip goes past them at other
  inputs (§6.1).
- Exponent overflow/underflow returns the correct mantissa and an exponent off by 128 (the
  7-bit field wraps) — the result is not clamped.
- Status bits other than BUSY are undefined while BUSY = 1.
- NOP clears the whole status byte.
- Data or command access while BUSY holds PAUSE̅ until the command ends; a status read does not.
- The stack is a 16-byte ring; a pop past empty re-reads old data; a misaligned pointer stays
  misaligned until RESET.
- "Lost" stack cells after a command hold scratch values. Their contents are not specified,
  but after a derived function they show the chip's steps (§6.1).
- END̅ is active low and open drain on the 9511A (active high on the 9512 — the SS-1's J6).
- ⚠ Four print faults in FPM ch.9 (SIN "0.1", TAN 2/π, both ASIN branches) are settled by
  arithmetic in §6; ⚠ the AMD range 9.2 × 10¹⁶ is a typo for 10¹⁸ (§3); ⚠ FPM Table 8.1's 456 as
  `09F40000` is a typo (§5).
