# SD Systems VDB-8024 Video Display Board

Source: [SDS_VDB8024.pdf](#)

SD Systems (SD Sales), Dallas TX. The VDB-8024 is an S-100 **video display board**: an
80-column × 24-line video terminal on one board, with an onboard keyboard interface, meant as
the console for an SBC-100/200 machine (the "video board and keyboard" alternative to the
SBC's 8251 serial console — see [`SD Systems SBC-100 & SBC-200.md`](SD%20Systems%20SBC-100%20%26%20SBC-200.md)).
Its scan is generated by an SMC **CRT 5027** video timer and controller; the terminal logic is
run by an **onboard Z80** executing firmware in a PROM, with a private RAM screen buffer and a
programmable character-generator PROM. With a monitor and an ASCII keyboard attached it is a
complete terminal.

This is a distilled emulation reference. Kit-assembly steps, the parts list, PCB-placement and
schematic-level IC walk-through, voltage-check and alignment procedures, and marketing from the
original manual are intentionally omitted; only what is needed to emulate the board in software
is kept. The manual was read from the deramp.com scan
`https://deramp.com/downloads/sd_systems/Manuals/SDS_VDB8024.pdf`; register and control-code
numbers are corroborated against two archived onboard-firmware sources (see §7).

**Important framing.** Despite the name, the VDB-8024 is **not** a memory-mapped video board —
it does **not** place a screen buffer in the host's address space. To the S-100 host it is
purely an **I/O device occupying two ports** (status + data), behaving like a serial terminal
with parallel handshake. The screen RAM, the CRT 5027, and the 5027's registers all live behind
the onboard Z80 and are invisible to the host. Emulate the host-visible terminal, not the
5027.

---

## 1. What the board is

- **Onboard Z80 microprocessor** — runs the terminal firmware (control-code interpreter, cursor,
  scroll, enhancement). It runs only during H & V sync (retrace) so it never disturbs the raster.
- **SMC CRT 5027** video timer/controller (VTAC) — character/line/row counters, cursor, H-sync,
  V-sync, blink. Programmed by the onboard Z80 at power-up.
- **Screen RAM** — private to the onboard Z80; holds the 80×24 character page. Not on the S-100
  bus.
- **Control PROM** — the terminal firmware. **CGEN PROM** — a 2708/2758/2716 programmable
  character generator (§6).
- **Host interface** — one output port (host → display) and one input port (keyboard → host),
  plus a status port. This is the entire S-100 footprint (§2).
- **Display** — 80 characters/line × 24 lines/page; 7×8 dot cell in a 7×10 field (2 descender
  bits) for upper/lower case; 128 characters typical (1K×8 CGEN), 256 with a 2K×8 PROM.
- **Monitor output** — composite video on J3, plus separate TTL H-sync, V-sync and video
  (positive- and negative-true) on header J2. Coax to the monitor.

## 2. Host interface — the two I/O ports

The board answers **two consecutive I/O ports** (the manual uses hex throughout; octal shown for
Altair convention):

| Port | octal | `IN` | `OUT` |
|------|-------|------|-------|
| **00H** | 000 | **status** byte (below) | — |
| **01H** | 001 | **keyboard** data byte (7-bit ASCII) | **display** data byte — character or control word |

These are the board's defaults and are hard-wired; the manual documents no host base-address
jumper, so the VDB is a fixed **port 00H/01H** device. (§2-8 calls them "initially addressed
with port 0 for status and port 1 for data".)

### 2.1 Status byte — `IN 00H` (both flags **active-HIGH**)

| Bit | Name | Meaning |
|-----|------|---------|
| **D1** | keyboard ready | **1** = a keyboard byte is waiting at `IN 01H`; 0 = none. Set by the keyboard strobe; cleared when the host reads port 01H. |
| **D2** | display ready | **1** = the display will accept a byte at `OUT 01H`; **0** = busy. Writing port 01H clears this bit (busy) and interrupts the onboard Z80, which reads the latch and sets it back to 1 (ready). |

D0 and D3–D7 are undefined. (§2-10 phrases D2 as "goes low to indicate the output port is
busy" — the same flag, active-high-ready / active-low-busy.)

### 2.2 Polling idioms (the emulation test vectors, from §6-2)

```
INPUT:  IN  A,(00H)      ; read status
        AND 02H          ; keyboard ready = D1
        JP  Z,INPUT      ; loop while 0
        IN  A,(01H)      ; read keyboard byte

OUTPUT: IN  A,(00H)      ; read status
        AND 04H          ; display ready = D2
        JP  Z,OUTPUT     ; loop while 0
        LD  A,C
        OUT (01H),A      ; send char/control word to display
```

**Keyboard** — any ASCII-encoded keyboard with **7 data bits + a strobe** (§2-12). It connects
to 16-pin header U13 (+5 V, GND, strobe, D0–D6). The strobe latches the 7 bits and raises status
D1; the host reads port 01H, which clears the latch.

**Independent host-side confirmation.** The **SD** build of the boot monitor,
`SDMONV21.Z80` ("SD monitor v2.10 for SBC-100 and VDM Console"), drives exactly this interface:
its console-input routine is `MCONST: IN A,(00H) / AND 02H` (status **D1**) then `IN A,(01H)`
(data), and it equates `CSTAT EQU 00H` / `CDATA EQU 01H`. That is the SD/MS monitor's "video
console" build — the counterpart to the **MS** build's 8251 at `7C/7D`
(see [`SD Systems Monitor.md`](SD%20Systems%20Monitor.md)) — and it corroborates the port map and
D1 polarity above from software written for the board.

## 3. Display format and character generator

- **80 columns × 24 lines** per page.
- **Character cell** 7×8 dots, displayed in a **7×10** field: bit 0 of each CGEN byte is *not* a
  dot — it flags whether that byte's two rows are drawn on lines 0/1 (ascenders) or lines 8/9
  (descenders), giving true lower-case descenders. Each glyph is 8 bytes; CGEN address bits 3–9
  are the ASCII code, bits 0–2 the row.
- **CGEN size** — a 1K×8 PROM holds 128 glyphs; a 2K×8 holds 256. The high 128 (the "expanded"
  set) can be selected per-character by special control bit #1 (§6), or the low 128 supplemented
  by the **extra character set** (§4, Table 3-1: 32 Greek/math symbols reached via `Ctrl-C`).
- The CGEN is a socketed PROM; replacing it changes the font. There is **no** host-visible
  character RAM — the host never addresses glyphs, only sends ASCII codes to port 01H.

## 4. Terminal control codes (`OUT 01H` control words)

The firmware interprets control bytes written to port 01H. The shipped-firmware set (§III):

| Code | Ctrl | Function |
|------|------|----------|
| 01H | A | Scroll-**Up** mode (default) |
| 02H | B | Scroll-**Down** / reverse-scroll mode |
| 03H | C | next byte = **special character** from the extra set (Table 3-1); affects only the one following char |
| 04H / 05H | D / E | special control **bit #1** ON / OFF (§6) |
| 06H / 07H | F / G | special control **bit #2** ON / OFF (§6) |
| 08H | H | **backspace** — non-destructive cursor left, stops at left margin |
| 09H | I | **tab** to next multiple of 8 columns *(inferred: the letter is not named, the function is §3-5)* |
| 0AH | J | **line feed** — cursor down; a feed on the last line triggers a scroll |
| 0BH | K | cursor **up** one line, stops at top |
| 0CH | L | **forward space** — non-destructive cursor right *(inferred)* |
| 0DH / 0EH / 0FH | M / N / O | display **speed**: slow / medium / fast (≈300 / 2400 / 19200 baud equivalents; asynchronous, not a real baud rate) |
| 11H | Q | **Quit** enhancement — end the current enhancement field |
| 12H | R | **reverse-video** field |
| 13H | S | **blinking-reverse** field |
| 14H | T | **blinking** field (75% duty) |
| 15H | U | **underline** field |
| 16H | V | **blinking-underline** field |
| 17H | W | **no-enhancement** field (lets a plain field be protected) |
| 18H | X | **protect** mode ON — enhancement fields become non-overwritable |
| 19H | Y | protect mode OFF (unprotect) |

**Cursor addressing:** `ESC = Y X` positions the cursor, where ESC = **1BH**, `=` = **3DH**, Y =
row + 20H, X = column + 20H.

**Enhancement rule:** only one enhancement *type* is active per page; entering a second type
retroactively changes all fields to the newest type. A field runs from its start code until
`Ctrl-Q`.

> **Firmware dependency (be honest):** the shipped SD firmware described above assigns **no**
> carriage-return, clear-screen, or home code, and it reuses 0DH (normally CR) for "slow speed".
> The two archived onboard firmwares in §7 implement a fuller and partly **different** map
> (e.g. `0DH`=CR, `1AH`=clear screen, home, insert/delete line, erase-to-EOL/EOS). Control-code
> semantics therefore depend on which PROM is fitted; an emulation must pin the firmware it
> reproduces. Prefer the manual's Section III set unless matching a specific firmware image.

## 5. Video enhancement and protect fields

Reverse, underline, blink and their blink combinations are *field* attributes toggled by the
codes above and terminated by `Ctrl-Q`. The **protect** field (`Ctrl-X`/`Ctrl-Y`) marks an
enhancement (or a `Ctrl-W` plain) field as non-overwritable — a form-fill feature. In the
archived firmware the per-character enhancement bit is memory bit D7 and protect is read back
from that bit; the shipped firmware carries the same idea. For emulation, model an 80×24 grid of
(char, attribute) cells where attribute ∈ {normal, reverse, blink, underline, blink-reverse,
blink-underline} plus a protect flag.

## 6. Jumper options (§VII)

Options are **hard-wired by default**; jumpers change them. There is no port-address jumper.

- **Character-generator PROM type (Table 7-1).** Default **2708** (jumpers E3-E9, E5-E6, no
  etch cut). For **2758**: jumper E3-E1, E5-E2, cut E3-E9. For **2716**: jumper E3-E1, E5-E11,
  cut E3-E4 and E5-E6. *Both* CGEN PROMs must be the same type.
- **Cursor type (Table 7-2).** Board ships with **E7-E8 and E9-E10 both installed = blinking
  underline** cursor. Reverse = *no* jumpers; underline = E7-E8; blinking reverse = E9-E10;
  blinking underline = both. Etch must be cut to change.
- **Special control bits.** Bit #1 (codes `Ctrl-D`/`Ctrl-E`) is a general output — e.g. jumper
  **E11-E7** to make it select the upper/lower half of a 2716 CGEN (two character sets, such as
  ASCII vs. APL). Bit #2 (codes `Ctrl-F`/`Ctrl-G`) is output on jumper **E12** — e.g. a monitor
  brightness control. These bits are otherwise user-defined.
- **Interrupt mode.** Default the host **polls** status. Alternatively the keyboard can raise an
  S-100 vectored interrupt (bus pins 5–8) by jumpering **E17 to one of E13–E16** (priority
  choice), for use with the SBC-100's mode-2 vectored interrupts. E17 emits a ~10 µs strobe.

## 7. Onboard architecture (illustrative — not host-visible)

None of this is visible to the S-100 host; it matters only to someone reimplementing the
terminal firmware. Two archived onboard-firmware sources corroborate the register map: an SD
Systems driver **VDB (v1.6, 1979)** and Bruce Jones's **VDB (v11, 1982)** with line insert/
delete and EOL/EOS. In the onboard Z80's own I/O space:

| Onboard port | Use |
|--------------|-----|
| **80H–8EH** | CRT 5027 registers (80H horiz-line-count … 86H last-displayed-row, 8AH reset, 8CH/8DH cursor column/line, 8EH start-timing-chain) |
| **10H** | control / enhancement latch (attribute + special-control-bit outputs) |
| **20H** | the host's output latch — a character written by the host arrives here (interrupt-driven) |
| **30H** | keyboard-ready flip-flop (physical keyboard) |

The screen buffer is in the onboard RAM. The driver sources use `1000H` as the buffer base with
128-byte (`80H`) row stride; per the archive maintainer this `1000H` is a **firmware-internal
RAM address, not a system/S-100 address** — treat it as illustrative only. Because the host
cannot see any of this, an altairsim board should model the terminal behavior directly (an 80×24
attributed grid driven by §2/§4), not emulate the Z80 or the 5027.

## 8. Emulation checklist (load-bearing facts)

- **Two I/O ports only — NOT memory-mapped.** Port **00H** = status (`IN`), port **01H** =
  keyboard (`IN`) / display (`OUT`). Fixed address, no base jumper. Zero S-100 memory footprint.
- **Status port 00H, active-HIGH:** D1 = keyboard byte available (cleared by reading 01H);
  D2 = display ready to accept a byte (cleared → busy by `OUT 01H`, restored when the firmware
  consumes it). Other bits undefined.
- **Display = 80 columns × 24 lines**, 7×8 cell in a 7×10 field (descenders via CGEN bit 0);
  128-glyph CGEN (256 with a 2K PROM). No host-visible character RAM.
- **Control words go to port 01H.** Shipped-firmware map (§4): scroll up/down (`^A`/`^B`),
  special-char prefix `^C`, control bits `^D`–`^G`, backspace `^H`, LF `^J`, cursor-up `^K`,
  speed `^M`/`^N`/`^O`, enhancement `^Q`–`^W`, protect `^X`/`^Y`, and `ESC = Y X` (row/col +20H).
- **Control-code semantics are firmware-dependent** — the archived firmwares add CR/clear/home/
  insert-delete and remap some codes. Pin the firmware you reproduce; default to §4.
- **Jumpers:** CGEN 2708 (default)/2758/2716; cursor defaults to blinking-underline (E7-E8+
  E9-E10); special control bits #1/#2 are user outputs; keyboard interrupt optional via
  E17→E13–E16. Polled by default.
- **Keyboard:** 7-bit ASCII + strobe (header U13). **Monitor:** composite (J3) + TTL H/V-sync +
  video (J2).
